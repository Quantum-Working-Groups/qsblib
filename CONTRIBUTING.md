# Contributing to QSBLIB

We welcome contributions from the public to the Quantum Simulation Benchmarking Library! This guide outlines how to submit problems and their associated latest benchmarks.

## Submission Process

To contribute a problem instance, please submit your results via **Pull Request** to this repository. 

Please follow the guidelines below when preparing your submission.

1. **Review the requirements and guidelines** located below this outline.
2. **Fork the repository** on [GitHub](https://github.com/Quantum-Working-Groups/qsblib/).
3. **Commit your new/updated problem file** to `/website/_problems/`, using the provided template [here](/qsblib/website/assets/templates/problem_template.md).
4. **Commit your new/updated solution file** to `/website/_solutions/`, using the provided template [here](/qsblib/website/assets/templates/solution_template.md).
5. **Open a PR against `main`**. Every PR requires approval from at least two committee members.

## Submission Requirements

Submissions must meet all of the following requirements before the QSB-Lib committee will review them. If any requirement is unmet, your pull request (PR) will be rejected with a brief explanation of what needs to be fixed.

_Note: Repeatedly submitting rejected PRs without resolving the flagged issues may result in your GitHub account—along with any associated accounts—being blocked from making future submissions._

1. **General scientific discipline:** Submissions must follow standard scientific best practices, including ethical guidelines for reporting research, proper attribution, and rigorous analysis.

2. **Peer-reviewed solutions and results:** While sharing early benchmark results on preprint servers (e.g., arXiv) is common practice, results must be peer-reviewed and published before they can appear in QSB-Lib. However, you may state that testing is underway for a specific problem or solution and link to an arXiv preprint, provided you do not include the unpublished result data directly in your submission.

3. **Completed fields:** Complete all mandatory fields as outlined in the submission templates. Not all fields are required; refer to the instructions within each template for details.

4. **"Submitted by" field:** Although you may submit using any verified GitHub account, you must designate a single individual as the primary point of contact. This person is accountable for the accuracy of the submission and will receive all related correspondence. Additional contributors may be credited in the "Contributions by" field.

5. **"Contributions by" field:** List any other individuals who contributed to the submission (if applicable).

6. **"Super Intelligence" (SI) use:** QSB-Lib takes a neutral stance on using SI to create, review, or correct problems and solutions. However, in the spirit of transparency, you must disclose whether SI was used at any stage of the process. At a minimum, you must answer "Yes" or "No" in the designated field for both problem and solution submissions (you are welcome to specify the extent to which SI was used). Regardless of SI assistance, the individual listed in the "Submitted by" field holds ultimate responsibility for the submission and must correct any inaccuracies or AI-generated errors ("hallucinations") prior to submitting.

## Questions?

If you have questions about the submission process or guidelines, please contact the maintainers or open an issue in this repository.

Thank you for contributing to the QSB-Lib!
